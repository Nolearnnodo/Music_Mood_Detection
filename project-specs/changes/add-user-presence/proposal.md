# Proposal: Mood Radio — User Presence & Community Mood

## Why

Mood Radio 目前是单机体验:用户只能看到自己的情绪和歌单。HCI 课程项目希望加入**人机交互之外的轻社交维度**:
让用户知道"此刻还有多少人和我一样开心"、"哪首歌正在被多少人同时听"。

这种"群体在场感"(presence)不需要传统账号、不暴露隐私、不引入复杂关系图,
仅作为一个**柔和的归属感反馈**,符合本应用的沉浸式电台定位。

## What

引入轻量级用户系统 + 实时在场聚合:

1. **匿名身份**:首次访问浏览器自动生成一个 user_id + 随机昵称(可改),保存在本地。无密码、无邮箱。
2. **在场心跳**(presence):前端每 60 秒上报一次当前 `mood_label / valence / arousal / current_track_id`。
3. **群体聚合**:后端按 5 分钟窗口聚合,提供"当前情绪分布"和"当前正在听的曲目 Top N"。
4. **社区面板**:新页面 `/community`(或电台页一个小卡片)展示聚合结果。
   不展示个人列表,**只展示数字**:
   - 「34 位用户当前开心,12 位平静」
   - 「现在最多人在听:夜に駆ける(7 人)、Always Online(5 人)」

## Goals

- 增加一个"集体情绪温度计"维度,让单机体验产生群体归属感
- 严格匿名:不展示 user_id、不展示 IP、不能反向定位某个用户在听什么
- 后端实现尽量薄:复用现有 SQLite,不引入额外服务

## Non-Goals

- 不做关注 / 好友 / 私信 / 评论等社交关系
- 不做账号注册 / 登录 / 密码 / OAuth
- 不做跨服务器的实时推送(无 WebSocket),只用 HTTP 轮询
- 不做反作弊;HCI 课程演示场景信任前端
