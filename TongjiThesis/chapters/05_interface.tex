\chapter{交互界面与视觉设计}\label{chap:interface}

如果说前两章把「任务 $\to$ 流程 $\to$ 结构」搭起来的是骨架，那么这一章就是要让骨架上长出血肉。下面先用一节交代贯穿全局的视觉系统，再依次走进 Mood Radio 的 8 个核心页面，逐一描述它们的布局、关键交互以及背后倚仗的 HCI 原则。每个页面的描述中，HCI 知识点不再作为单独罗列的「给分点」摆出来，而是融进对设计决策的讨论里——这样既不丢掉评分维度，也更接近一份让人愿意读下去的设计说明。所有页面的实际截图位置已在本章插图中预留。

\section{视觉系统总览}

\subsection{情绪主题（Mood Theme）}

视觉变化是 Mood Radio 最容易被用户「一眼看出」的特征。系统配置了 7 套情绪主题色 $\times$ Light/Dark 两套基底，合计 14 套配色，通过给 \verb|<html>| 节点的 \texttt{data-mood} 属性赋值进行切换。\cref{tab:mood-theme}~给出 Dark 模式下的强调色对照。值得说明的是，每一套主题的色彩选择都并非纯粹的审美决定：愤怒情绪刻意避开了「大红」，因为大红在长时间凝视下反而会引发压抑感；焦虑情绪选用了中性灰，目的是不在用户已经紧绷的状态上再叠加视觉刺激。这种「不强行改变用户情绪」的伦理边界在视觉层面也被认真对待。主题切换借助 CSS 自定义属性配合 500\,ms 的过渡完成，避免颜色突变造成的额外刺激。

\subsection{Aurora 流动背景与黑胶旋转封面}

光是切换主题色还不足以传达「系统正在跟随我」的感觉，因此课题组在背景层加了一道流动的「极光」。\verb|body::before| 与 \verb|body::after| 是两个 85\,vw 大小的径向渐变色块，分别施加了 80\,px 的模糊后以 22 秒和 26 秒两个略有差异的周期缓慢飘动；它们的颜色 stop 跟随当前主题，于是用户在屏幕下方始终能看到一团缓慢流动的「情绪光晕」。

播放器层引入的 \texttt{VinylDisc} 组件是同样思路的另一种表达。它是一个 SVG 黑胶圆盘，圆周上画了 10 圈凹槽与一条反射高光，中央放置着正方形的封面贴纸，并以 7 秒一圈的线性旋转动画转动。这里有一个值得强调的设计判断：\textbf{黑胶只在播放时旋转}。如果切到暂停状态，它会立刻停下来。这个看似微不足道的细节其实承担了一个重要的反馈作用——用户哪怕没看到播放按钮，也能在余光中通过它判断系统是否在放歌。

\subsection{封面沉浸背景与玻璃质感}

\texttt{CoverBackdrop} 组件在切歌时把当前歌曲的封面经过 \texttt{blur(22px)}、\texttt{saturate(1.4)} 与 \texttt{brightness(0.7)} 的滤镜，再叠加一层黑色渐变蒙版作为整页背景；跨曲时背景之间会有 1.2 秒的交叉淡入。在它之上，所有卡片都共享 \texttt{.glass} 工具类，使用 \texttt{backdrop-filter: blur(14px)} 形成半透明的玻璃质感，让 Aurora 与封面背景能够透过来。最终的视觉语言是「玻璃悬浮于光晕之上」——一种相对克制的沉浸感，不会喧宾夺主。

\section{首页电台 / \texttt{/radio}}

\texttt{/radio} 是用户进入系统后看到的第一屏，也是整套交互的核心。它在垂直方向上被分为三层：顶部是包含主导航、主题切换与个人徽章的 TopNav；中部是情绪输入面板，左侧承载摄像头预览与稳定徽标，中部是 7 选 1 的手动情绪按钮，右侧呈现「当前时段卡片」与「自动续推开关」；下部是推荐结果区，每一首推荐曲目卡片旁都会带有一组小徽标（喜欢 / 新鲜 / 最近），承担可解释性反馈的角色。右下角全程驻留着浮动的 GlobalPlayer。\cref{fig:radio}~给出运行截图位置。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{6cm}\hspace{12.5cm}}
  \caption{\texttt{/radio} 页面运行截图（\textit{待嵌入}）}\label{fig:radio}
\end{figure}

这一页是\textbf{多模态冗余}原则的最直观体现：摄像头、手动按钮、时段卡片同处一屏并被同等地呈现，用户可以按当下偏好挑选任意一条通道而不会觉得「另一条更高级」。\textbf{显式输入与隐式输入}在这里也共存——「7 选 1」按钮属于显式输入，摄像头识别与时段判断属于隐式输入，但它们会被统一翻译成同一种格式的事件后进入下游，因此用户视角下只看到一致的反馈。「\textbf{匹配 / 安抚}」开关与「自动续推」开关都被刻意放在显著位置，这一选择对应「\emph{用户可控}」原则——任何会决定后续若干分钟体验的关键判断都应该由用户来做，而非系统替用户做主。当推荐返回后，主题色与背景的同步切换又一次扮演了\textbf{即时反馈}的角色——它把抽象的「推荐成功」翻译为肉眼可见的视觉变化，从而把整条流程的「我说话 $\to$ 系统回应」的感觉钉死在 1 秒之内。最后，推荐列表中的徽标对应了\cref{sec:reco}~所定义的复合打分项，让算法对用户透明，是「\textbf{可解释性}」原则在此页面的落地。

\section{LLM 聊天推荐 / \texttt{/chat}}

\texttt{/chat} 采用对话式 UI——左侧（或上方）是消息流，下方是输入框与发送按钮。助手返回的气泡里，除了文本之外还嵌入了「识别到的情绪徽标」与「一键播放」按钮，因为 LLM 的输出会被强制要求返回 \texttt{\{reply, mood, target\}} 这样的结构化 JSON，于是可以直接转换为推荐参数。\cref{fig:chat}~给出运行截图位置。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{5.5cm}\hspace{12.5cm}}
  \caption{\texttt{/chat} 页面运行截图（\textit{待嵌入}）}\label{fig:chat}
\end{figure}

聊天页最显著的 HCI 价值在于把\textbf{自然语言交互}的入口打开了——用户可以用任何句式描述情绪，包括那些 7 类标签覆盖不到的微妙状态（如「有点空落落但又懒得动」）。但是「自然语言」并不等于「自由聊天」：如果让 LLM 闲聊几句却不能转化为可执行的操作，反而会浪费用户的耐心。为此课题组在 system prompt 中明确强制 LLM 返回结构化 JSON，把对话\emph{受控}地限制在「描述情绪 $\to$ 翻译成推荐参数」的窄通道里。助手气泡显式展示了「我识别到你是 X 情绪，所以推荐这些歌」的解释，这是\textbf{可解释性}的另一种形态。最后，由于这一页涉及到外部 LLM 服务，\textbf{隐私边界}必须被显式告知用户：首次使用时弹出一段说明，提示 API Key 仅存放于浏览器，不会进入后端日志。

\section{曲库管理 / \texttt{/library}}

\texttt{/library} 承担着「查看与管理本地音乐库」的功能。页面顶部是四象限筛选 + 关键词搜索 + 排序工具条，中部是网格化的曲目卡片——每张卡片以专辑封面为底，叠加歌曲名与 V/A 标签；点击任意卡片会从右侧滑出详情面板，里面包含黑胶预览、重新分析、删除以及喜欢 / 不喜欢按钮。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{6cm}\hspace{12.5cm}}
  \caption{\texttt{/library} 页面运行截图（\textit{待嵌入}）}\label{fig:library}
\end{figure}

这一页的核心交互模式是「master--detail」——筛选区域负责\emph{多对一选择}，详情面板负责\emph{深入一项}。从 HCI 视角看，这种\textbf{多视图协调}模式之所以好用，是因为它把「\emph{探索}」与「\emph{确认}」分成了两个心智阶段：用户先在网格中粗略浏览，等找到值得深入的曲目再点开。\textbf{容错设计}也在这一页有具体体现——删除前会弹出二次确认，而「重新分析」是一个无副作用、可重复触发的非破坏性操作。卡片上的 V/A 标签让用户能直接读到「这首歌为什么会出现在推荐里」的依据，是\textbf{可解释性}的延伸。最后，喜欢 / 不喜欢按钮在详情面板中尺寸较大且位置固定，遵循了 \textbf{Fitt 定律}的基本判断：高频操作的目标应当大而近。

\section{拖拽上传 / \texttt{/upload}}

\texttt{/upload} 的主体是一个大尺寸的虚线框，文案为「拖拽音频文件到此处」。当用户拖入文件后，虚线框变为带进度条的文件列表，每个文件在分析完成后会变为绿色对勾。页面底部固定一行小字提示：「分析在本地完成，文件不上传」。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{5cm}\hspace{12.5cm}}
  \caption{\texttt{/upload} 页面运行截图（\textit{待嵌入}）}\label{fig:upload}
\end{figure}

这一页的虚线框是教科书式的 \textbf{Affordance}——它以视觉上的「容器」隐喻提示用户「这里可以接住东西」，无需文字说明也能让用户知道该如何操作。每个文件的独立进度条对应 Nielsen 启发式的「\textbf{系统状态可见}」——避免出现「界面不动了，是不是死了」的怀疑。底部的小字看似只是装饰，实际上承担着重要的\textbf{隐私沟通}：很多用户在直觉上会把「拖文件到网页」等同于「上传」，明确的反向说明能够打消这一误解。

\section{情绪图谱 / \texttt{/mood}}

\texttt{/mood} 把曲库里所有歌曲在 Russell V/A 平面上的位置画了出来。主体是基于 Chart.js 的散点图，X 轴是 Valence，Y 轴是 Arousal，散点的颜色按情绪聚类分色；单击散点试听，双击则把该曲加入当前歌单；右侧抽屉展示选中曲目的「轨迹动画」，即一首歌的 V/A 值在 30 段窗口内的漂移轨迹。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{6cm}\hspace{12.5cm}}
  \caption{\texttt{/mood} 页面运行截图（\textit{待嵌入}）}\label{fig:mood}
\end{figure}

这一页是整个系统中\textbf{信息可视化}最为典型的体现：抽象的 V/A 数值被翻译成可直接感知的「位置」，让用户能在十秒之内对自己曲库的「情绪分布」有一个直观判断。它也提供了一种与\texttt{/library} 截然不同的入口模式——\textbf{直接操纵}：在图上鼠标圈选歌曲就等同于「我想听这一片」，省去了「先按标签筛选、再加入歌单」的两步流程。散点的颜色与\cref{tab:mood-theme}~中的主题色保持一致，是「\textbf{对应一致性}」在视觉系统层面的延伸——用户在曲库页面看到的「黄色 = happy」与在情绪图谱里看到的「黄色 = happy」之间不存在歧义。最后，单击与双击两种操作分别对应「试听确认」与「加入歌单」，形成「\textbf{探索 + 确认}」两层心智的操作模式，与 \texttt{/library} 的 master--detail 在思路上一脉相承。

\section{心情日志 / \texttt{/journal}}

\texttt{/journal} 在时间维度上做文章。页面顶部是「过去 90 天」的日历视图，每一格按当天主情绪着色，未记录日子则为浅灰；中部是「过去 7 天」按情绪类别堆叠的柱状图；底部是按时间倒序的详细日志列表，每一条携带情绪、来源、策略与坐标。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{6cm}\hspace{12.5cm}}
  \caption{\texttt{/journal} 页面运行截图（\textit{待嵌入}）}\label{fig:journal}
\end{figure}

「90 天日历 + 7 天柱状 + 详细列表」三个视图分别对应「俯视、回顾、查询」三种不同尺度的决策需要，是\textbf{时间尺度切换}的实践。这一页的设计有一个不那么显眼但很重要的伦理判断：日志的本意\emph{不是评分用户的情绪}，而是让用户「自我观察」，这与反思型设计（reflective HCI）的主张是一致的。日志数据全部保存在浏览器本地存储中，并不进入服务端数据库，进一步强化了\textbf{隐私优先}。

\section{群体此刻 / \texttt{/community}}

\texttt{/community} 是 Mood Radio 中最社交化的一页，但也是最克制的一页。它的顶部用一行大字告诉用户「现在 $N$ 人在线」，中部用横向条形图展示按情绪分类的人数分布，下方列出 Top 听单（带听众数与隐私门槛说明）。\textbf{这一页不会展示具体的用户}——所有数据都是聚合后的统计量。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{5.5cm}\hspace{12.5cm}}
  \caption{\texttt{/community} 页面运行截图（\textit{待嵌入}）}\label{fig:community}
\end{figure}

这种「只给数字不给名字」的设计本身就是一种 HCI 选择，对应「\textbf{弱社交陪伴}」的理念——用户能感受到自己并不孤单（有别人正在和我听类似情绪的歌），但又不至于产生「被注视」或者「我得回应一下」的社交压力。\textbf{隐私门槛}是另一个细节判断：当某首歌的听众数低于 $N$ 时，它根本不会出现在 Top 听单里，避免在小样本下被反推个人偏好。页面文案上还会明示「数据更新约 1 分钟」，把异步聚合带来的延迟显式化，体现\textbf{延迟一致性}——不主动制造「数据是实时的」错觉。

\section{偏好与隐私 / \texttt{/settings}}

\texttt{/settings} 按「监控目录、推荐偏好滑杆、LLM 配置、隐私与数据」四块分区，每块都使用一致的卡片布局，关键开关旁附带「这是什么意思？」的小问号弹出框。

\begin{figure}[!htb]
  \centering
  \fbox{\rule{0pt}{6cm}\hspace{12.5cm}}
  \caption{\texttt{/settings} 页面运行截图（\textit{待嵌入}）}\label{fig:settings}
\end{figure}

四个分区按用户心智组织（「文件 / 推荐 / 模型 / 数据」），方便定位，是\textbf{分组与可发现性}的体现。问号弹出框就近解释术语，让用户无需离开当前页面查文档，是「\textbf{帮助即位}」（help on-the-spot）的实践。「清空播放历史」与「重新分析全库」这一类不可逆操作被刻意放在每个卡片的末尾、并要求二次确认——这一布局体现了\textbf{破坏性操作分离}的设计判断，让「常规设置」与「危险动作」在视觉上保持一定距离。

\section{群体在场感的视觉表达}

最后还有一点值得单独提一下。\texttt{/community} 页面的横向条形图刻意采用了与主页同一套主题色，而不是另外画一套「群体专用色板」——这是为了避免「群体世界另开一种配色」的违和感。条形图会从左到右淡入（约 0.6 秒一次），既暗示「数据是实时的」，又避免了完全静态带来的「页面死了」的感觉。这些都是相当细微的判断，但它们组合起来才把「视觉、声音、文字共同响应同一情绪标签」这一原则贯彻到底。
