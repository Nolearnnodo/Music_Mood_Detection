\chapter{绪论}\label{chap:introduction}

\section{项目背景与研究意义}

很多人会把音乐当作一种「情绪调节器」。一边赶完代码的凌晨、一段冗长会议结束之后的午后，或是出门慢跑的清早，人们往往不是「想听某一首歌」，而是「想让自己进入某种状态」。心理学领域早在二十世纪八十年代就给出了一种很方便的解释：Russell 提出，绝大多数情绪都可以放在「愉悦--唤醒」（Valence--Arousal）这两个连续维度构成的圆环上\cite{russell1980circumplex}；如果再认定音乐本身也具有这两个维度，那么「音乐之于情绪」就不再是玄学，而是一种坐标到坐标的映射关系。这一映射正是本课程设计赖以展开的基础。

与此同时，主流商业音乐服务（如 Spotify、网易云音乐、Apple Music 等）经过十余年的演化，在「依据历史偏好为用户挑歌」这件事上已经做得相当成熟\cite{ricci2015recommender}。它们能在用户每天打开 App 的时候推送出风格合宜的「每日推荐」，并且大致猜得到用户最近是不是又开始喜欢某一类音乐。然而，这种以\emph{长期偏好}为强信号的方式在两类时刻表现得相当吃力：一是当用户的情绪与一贯偏好突然脱节时——例如平日里偏爱明快电子的人因为某次失眠而想找点纯钢琴；二是当用户连自己想听什么都说不清楚、只想要「合适此刻」的歌单时。换言之，它们解决了「长期喜好」，却没有正面处理「此刻状态」。

这一空白对人机交互（Human--Computer Interaction，HCI）课程而言是一个相当理想的练习题。它牵涉到多模态输入（如何捕获用户的当下情绪）、情境感知（如何让系统理解输入背后的语义）、可解释推荐（如何把算法判断翻译成用户能看懂的反馈）以及隐私保护（如何在不过度采集数据的前提下完成上述能力）这些核心议题；同时它又落在一个普通用户每天都会接触的场景里，避免了为练习而练习的空洞。这构成了本课程设计的出发点。

\section{现有方案的不足}

围绕「让系统替我挑一首合适的歌」这一目标，现有方案存在三个共同的弱点。\emph{第一}是\textbf{对即时情绪不敏感}。无论是协同过滤还是基于内容的相似度匹配，背后假设的都是「用户偏好是相对稳定的」。这一假设在大多数日常场景下成立，但在情绪波动的关键节点上恰好失效；而恰恰是这些节点最希望被音乐回应。\emph{第二}是\textbf{交互通道单一}。多数应用只接受「搜索 + 点击」这一种显式输入，几乎不利用摄像头、自然语言、时段、姿态等更轻量的隐式信号。后者的缺位意味着用户哪怕只想表达「现在心情不太好，给点温和的歌」，也得在脑海里先把这个感受翻译为一组关键词或一份歌单标题，才能让系统理解。\emph{第三}是\textbf{隐私边界与可解释性的同时缺失}。情绪与面部画面被广泛认为属于敏感数据，而商业系统出于推荐效果的考虑，常常把这类数据上传到云端做集中分析；用户既无从知道数据被如何使用，也不知道推荐背后的依据。这种「黑箱 + 上云」的组合对那些珍视隐私、又希望系统给出解释的用户极不友好。

\section{课程设计的目标}

基于上述背景与不足，本课程设计提出并实现了一个面向\emph{本地音乐库}的情绪感知电台，命名为 \mbox{Mood Radio}。系统的整体目标可以概括为「让一台个人电脑——而不是云端服务器——根据用户此刻的情绪，从用户自己的音乐库里挑一组合适的歌」。这一目标隐含了几条相互呼应的子目标：在输入侧，希望覆盖摄像头表情、手动选择、自然语言聊天、时段推断、头部手势这五条互为冗余的通道，使得即便其中任何一条不可用，系统也仍然能正常工作；在表示侧，希望把「人的情绪」与「音乐的情绪」放进同一坐标空间，以 Valence--Arousal 这一公共语义统一处理；在打分侧，希望把推荐的依据——情绪距离、用户的喜欢/不喜欢、新鲜度、最近播放时间——显式暴露给用户而非藏在算法内部；在视觉侧，希望让页面色调、流动背景、播放器封面都随当前情绪柔和变化，把抽象的「系统正在理解我」翻译为可被肉眼感知的反馈；在隐私侧，希望摄像头画面、音乐文件全程不离开本机，同时把 LLM 的 API Key 仅保留在浏览器，让所有可能涉及个人的数据都有明确的边界。这五个子目标贯穿了本报告之后所有章节的讨论。

\section{报告组织结构}

本报告共分八章。\cref{chap:introduction}（即本章）介绍项目的背景、动机与目标。\cref{chap:requirement} 围绕用户研究展开，覆盖问卷、情景访谈、焦点小组与单独访谈四种方法，从中提炼出三个具有代表性的目标用户画像，并把零散的痛点整理为一份可以追踪的需求说明书和需求框图。\cref{chap:design} 自顶向下给出系统的总体架构、技术选型、数据模型与对外接口；\cref{chap:task-flow} 把需求转化为具体的「\emph{用户做什么}」和「\emph{系统如何回应}」，包含任务一览、使用行为分析、顺序图、三个情节故事以及页面跳转图与交互结构图。\cref{chap:interface} 逐页给出界面设计与所运用的人机交互知识点，\cref{chap:implementation} 重点讨论 V/A 情绪建模与修复、多通道输入融合、复合打分推荐以及 LLM 子进程代理这四个最关键的功能模块。\cref{chap:evaluation} 给出小规模课堂评估的方法与结果，并附带在线/离线运行方式。最后，\cref{chap:conclusion} 总结全文并讨论局限与后续工作方向。
