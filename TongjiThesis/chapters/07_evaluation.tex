\chapter{可用性与用户体验评价}\label{chap:evaluation}

本章在小规模课堂环境下对 Mood Radio 开展\emph{形成性可用性评估}：先说明评估方法，再分别报告任务完成情况、用户满意度问卷与开放反馈，最后给出 HCI 原则与课程概念的映射，以及系统的在线/离线运行方式（满足课程对「可运行」的要求）。需要再次强调，本评估规模有限（$N = 10$），目的是检验系统是否满足 Persona 的核心诉求，而非追求统计显著性。

\section{评估目标与方法}

\subsection{评估目标}

围绕\cref{chap:requirement} 提出的需求与设计原则，本评估关注三个问题：

\begin{enumerate}
  \item 用户能否在不依赖讲解的前提下完成「打开 $\to$ 触发推荐 $\to$ 播放」这条最关键的任务路径？
  \item 用户是否能够\emph{理解推荐的依据}？
  \item 用户对系统的隐私设计、视觉反馈、可控性等关键属性是否满意？
\end{enumerate}

\subsection{评估方法}

本评估采取「\textbf{有声思考任务} + \textbf{5 级 Likert 满意度问卷} + \textbf{开放反馈访谈}」三段式方法：

\begin{enumerate}
  \item \textbf{有声思考任务}：受试者在不被引导的情况下，按要求完成三项任务（T1、T3、T7，参见\cref{tab:task-list}），主持人记录完成情况与卡点。
  \item \textbf{Likert 满意度问卷}：任务结束后立即填写一份 7 题的 5 级量表问卷，覆盖任务难度、推荐理解、隐私信任、视觉反馈、整体满意度等维度。
  \item \textbf{开放反馈访谈}：随后进行 5\,$\sim$\,10 分钟的半结构化访谈，让受试者补充未在问卷中体现的细节。
\end{enumerate}

\subsection{受试者}

10 名同班同学参与评估，男女比例约 6:4，年龄集中在 20\,$\sim$\,23 岁；其中 4 人首次使用本系统，6 人在原型阶段曾短暂接触过。每位受试者评估时长约 25 分钟。

\section{反馈与问题分析}

开放反馈访谈中，受试者贡献了若干\emph{结构化}的改进建议，可按类型归纳如下：

\begin{enumerate}
  \item \textbf{首次扫描音乐库较慢}。当个人音乐库较大（数百首）时，初次扫描伴随特征提取，会有几十秒到分钟级的等待；多名受试者提出「我以为系统卡死了」。改进方向：扫描期间增加进度提示与 ETA。
  \item \textbf{弱光下表情识别不稳定}。face-api.js 在背光、侧脸或大幅遮挡场景下置信度显著下降，「系统老识别成 neutral」是高频反馈。改进方向：低置信度时主动建议切换到手动通道。
  \item \textbf{小型曲库下推荐多样性不足}。当个人本地音乐库小于 50 首时，复合打分会反复推送少数几首高分曲目；改进方向：在打分中加入「同情绪曲目轮转」项。
  \item \textbf{聊天偶发网络失败}。一例由 LLM 网络问题导致的失败暴露了「错误状态」的缺失：当前页面没有清晰提示「请检查 LLM 配置」。改进方向：增加错误状态卡片与重试按钮。
  \item \textbf{授权弹窗位置}。多名受试者抱怨浏览器的摄像头权限弹窗「不知道点哪里」。这是平台层而非应用层的问题，但可以通过「弹窗前预先展示一张引导图」缓解。
\end{enumerate}

\section{在线 / 离线运行方式}

为方便课程评审与同学复用，Mood Radio 同时提供「\textbf{离线本地运行}」与「\textbf{在线开发模式}」两种启动方式。两者都以 \texttt{start.ps1} 一键脚本作为入口，差别仅在传入的参数上。\cref{tab:run-mode}~给出运行方式与依赖。

\begin{table}[!htb]
  \centering
  \caption{Mood Radio 的两种运行方式}\label{tab:run-mode}
  \begin{tabularx}{\linewidth}{lXX}
    \toprule
    \textbf{模式} & \textbf{命令} & \textbf{说明} \\
    \midrule
    完整离线运行 & \texttt{.{\textbackslash}start.ps1} & 后端新窗口 + 前端 dev；除聊天功能外完全离线 \\
    仅后端       & \texttt{.{\textbackslash}start.ps1 -BackendOnly}  & 只跑 C++ 后端 + SQLite，便于联调推荐接口 \\
    仅前端       & \texttt{.{\textbackslash}start.ps1 -FrontendOnly} & 只跑 Vite dev server，便于 UI 改样式时热刷 \\
    \bottomrule
  \end{tabularx}
\end{table}

后端默认监听 \texttt{127.0.0.1:8080}，前端 dev 默认监听 \texttt{5173}，并通过 Vite 的 \texttt{/api $\to$ 8080} 反向代理对接。\cref{lst:run}~给出一次性的安装命令与启动命令。

\begin{lstlisting}[
  caption={Mood Radio 一次性安装与启动},
  label=lst:run,
  basicstyle=\ttfamily\footnotesize,
  numbers=none,
  escapeinside={},
  mathescape=false,
  float=!htb,
]
# 一次性安装（仅首次需要）
cd frontend\web && npm install  ; cd ..\..
cd scripts && uv venv --python 3.12 .venv ; ^
  uv pip install -p .venv/Scripts/python.exe ^
  onnxruntime librosa soundfile numpy ; cd ..

# 编译后端（MSVC 工具链 + vcpkg）
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=...
cmake --build build

# 启动（从仓库根）
.\start.ps1                # 后端新窗口 + 前端 dev
.\start.ps1 -BackendOnly   # 只跑后端
.\start.ps1 -FrontendOnly  # 只跑前端
\end{lstlisting}

聊天功能依赖外部 LLM 服务（如 DeepSeek、OpenAI 等），需要在 \texttt{/settings} 页面填入 \texttt{base\_url}、\texttt{api\_key} 与 \texttt{model}。这些参数仅存放于浏览器 \texttt{localStorage}，不进入后端数据库，符合\cref{tab:nfr} 中的 NFR-02。
